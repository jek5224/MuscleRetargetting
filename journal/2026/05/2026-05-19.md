## env.py P1 fix: arc-length weight inversion

`loading_zygote_muscle_info` had:

```python
mesh_names = [first, last]   # = [origin_body, insertion_body]
weights = [l_origin, l_insertion] / total
```

`weights[0]` (origin bone weight) = arc length FROM origin = SMALL near
origin. Inverted from LBS convention (closer bone → higher weight). For
intermediate waypoints, the muscle belly tracked the WRONG bone — near
origin it followed insertion bone, near insertion it followed origin
bone. Caused "weird motion" user observed.

Fixed: `weights = [l_insertion, l_origin] / total`. Endpoints unaffected
(DART skips weights for i=0 / i=N-1 and uses single-bone path).

## 3-bone LBS extension in `loading_zygote_muscle_info`

Added kinematic-chain detection between origin and insertion bone of
each fiber. Length ≥2 intermediates → biarticular → 3-bone LBS:
- `bn_names = [origin, intermediate, insertion]` (closest body in chain
  to fiber midpoint at rest, chosen per fiber)
- Tent weights at `u_m` (arc fraction where fiber crosses intermediate),
  clamped to [0.1, 0.9]

For chains with 0 or 1 intermediate (monoarticular Vastus, Glute, etc.),
fall back to 2-bone with the P1-fixed weights.

No C++ change needed — `addMuscleWeight` already accepts K-length
`bn_names + weights[i]`. Verified DART loads + simulates without errors.
