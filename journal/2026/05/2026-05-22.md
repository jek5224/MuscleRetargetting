# Research Journal — 2026-05-22

## Reverse-LBS XMLs for walk / run / combined

Added `tools/reverse_lbs_solve_multi.py` to solve per-waypoint K-bone LBS
across one or more (BVH, cache_template) sources.  Concatenates
waypoint trajectories and body transforms across sources before
least-squares.  Run three times to produce:

- `reverse_lbs_results_walk/` from walk.bvh ×
  `data/motion_cache/walk/{REGION}_iter50_nobone`
- `reverse_lbs_results_run/` from run.bvh ×
  `data/motion_cache/run/{REGION}_quads_tfl_skin`
- `reverse_lbs_results_combined/` from both stacked

`tools/write_reverse_lbs_xml.py` extended with `--src` / `--out`, embeds
`lbs_bones` / `lbs_locals` / `lbs_weights` per Waypoint and `stream` /
`fiber` per Fiber.  `level` attr dropped (waypoints written in level
order within each Fiber, loader uses enumerate index).

Residuals (per-muscle p95 worst-frame, mm):

| Source | Median p95 | Worst muscle | Worst p95 |
|--------|-----------:|--------------|----------:|
| walk     | 6.3  | R_Semitendinosus       | 22.7 |
| run      | 10.2 | R_Semitendinosus       | 31.4 |
| combined | 11.6 | R_Extensor_Digitorum_Longus | 36.7 |

Pattern: biarticular hamstrings + toe extensors worst.  Run ROM bigger
→ ~60% worse than walk.  Combined ≈ worst-of-two.

## Viewer reverse-LBS loader: XML instead of NPZ

`_reverse_lbs_load` now parses `data/zygote_muscle_LBS_combined.xml`
(default; constant `REVERSE_LBS_XML` at top of function).  Per-waypoint
K-bone arrays padded to max K per muscle, single einsum across all
waypoints in `_reverse_lbs_compute`.  Body transforms cached once per
frame across all muscles (was ~740 redundant DART calls per frame).

Bug fixed: XML emits waypoints per `(stream, fiber)` then level, but
scatter into `mobj.waypoints[stream][level]` expects `(stream, level,
fiber)` order.  Loader sorts raw waypoint list by `(s, l, f)` before
building padded arrays.

Toggle off restored: was no-op, leaving LBS-derived waypoints visible
until next frame advance.  Now reapplies cached deformation on current
frame and marks fibers dirty.

## Draw-path hardening (segfault fixes)

Toggle-time segfaults (fiber/tet/reverse-LBS draw on or off) traced to
`glVertexPointer` / `glColorPointer` being interpreted as offset into
a VBO another path left bound, or stale `GL_COLOR_ARRAY` enable leaking
from a previous frame.

Defensive at every fast-path / slow-path / tet draw entry:
- `glBindBuffer(GL_ARRAY_BUFFER, 0)` before any client-side array call
- `glDisableClientState(GL_COLOR_ARRAY / GL_NORMAL_ARRAY)` before
  enabling only what this draw uses

Test-fiber `pts` now keepalive'd (was per-frame local that may be GC'd
before glDrawArrays consumes).

## Fascia bake pipeline (per region)

Added `tools/build_fascia_mesh.py` + `tools/bake_fascia.py`.

`build_fascia_mesh.py`: one-shot rest geometry for 4 regions.  Per
region: union of muscle anatomical surfaces (`render_faces` minus
`cap_face_indices`), 3 mm outward dilation, voxel remesh at 5 mm pitch,
quadric decimation, per-fascia-vert barycentric binding to nearest
anatomical tri.  Saved as `data/zygote_fascia_rest_{REGION}.npz`.

Vert counts:
- L_UpLeg / R_UpLeg: ~32700 verts
- L_LowLeg / R_LowLeg: ~14000 verts

`bake_fascia.py`: per-region per-BVH bake.  Reuses bake_headless
load + init machinery, then **disables inter-muscle pins** by setting
`ctx.inter_muscle_constraints = []` (skips
`find_inter_muscle_constraints`).  Muscles slide freely.  After each
frame's muscle solve, fascia verts computed by barycentric pull from
current muscle anatomical tri positions.

Cache layout:
- muscles → `data/motion_cache/{bvh}/{REGION}_fascia/`
- fascia  → `data/motion_cache/{bvh}/fascia_{REGION}/fascia_chunk_*.npz`

First-cut limitations (deliberate):
- No explicit fascia ARAP (tension to rest).
- No cage feedback to muscles (no muscle-stay-inside-fascia push).
- Fascia rides muscles passively — validate visuals + drift first.

Verified: 5 frames walk.bvh L_UpLeg complete at ~0.9 s/frame.  Fascia
32 k verts coherent with muscle bake.
