# Research Journal — 2026-06-01

## 25-fiber resample + zygote_muscle_25.xml

Added a slider+Apply UI to Inspect 2D so a saved muscle anim can be
re-sampled to a new grid resolution without re-running the contour pipeline
or touching the underlying tet topology. Default grid count dropped from
10×10 to 5×5 across the codebase.

Pipeline used to roll out the 25-fiber XML:

1. Apply N=5 in the viewer on all L_* leg muscles, Save Tet.
2. `tools/mirror_tet_L_to_R.py` mirrors the L tets to R (must be run with
   pyMAC's older numpy or pyMAC can't unpickle the result).
3. `tools/save_tets_with_skel_attachments.py` re-runs `init_soft_body` so
   each muscle's `attach_skeleton_names` is populated and re-saved into
   `tet/{name}_tet.npz`. Without this, `reverse_lbs_solve_multi.py`
   segfaults on `addMuscleWeight` for muscles whose bone references aren't
   resolvable.
4. `tools/patch_25fiber_waypoints.py` reuses every existing
   `data/motion_cache/{walk,run}/{REGION}_*` chunk: loads each muscle's tet,
   inits soft body, iterates the saved tet vertex traces, regenerates
   `waypoints_flat` at 25-fiber count via `_update_waypoints_from_tet`.
   No re-bake needed.
5. `tools/reverse_lbs_solve_multi.py` combined walk×`iter50_nobone` +
   run×`quads_tfl_skin`. Median p95 residual hovered around prior
   numbers; biarticular hamstrings/toe extensors still worst.
6. `tools/write_reverse_lbs_xml.py` -> `data/zygote_muscle_25.xml` (74
   Units, 2500 Fibers, 25200 Waypoints — exact 4× shrink from the 100-fiber
   combined XML).

Viewer's `REVERSE_LBS_XML` constant flipped to `zygote_muscle_25.xml`.

## Skeleton XML edit mode + atomic save

Replaced the standalone "Edit Joint Positions" checkbox with an "Edit
Mode" master toggle under the Skeleton tree.

* On edge ON: walks every loaded skeleton mesh once and sets
  `is_draw_corners = True`. Per-mesh "Draw Corners" toggles stay
  independent between Edit Mode flips.
* Continuous (every frame while Edit Mode is on): derives world-space OBB
  corners from `new_skel_info` body_r/body_t/size via DART world
  transforms. Joint edits push the boxes around live without re-toggling.
  Also mirrors corners into `corners_list` so the "Connect to parent"
  overlap check at `zygote_mesh_ui.py:1430` actually iterates the new OBBs.
* Hierarchy seed on each ON edge: derives `is_root` / `parent_mesh` /
  `parent_name` / `children_names` from `new_skel_info`. Required because
  `exportBoundingBoxes` walks `children_names` from the root mesh, and
  without seeding the tree the save dropped any node the user hadn't
  manually connected.
* Bone-name → mesh-name resolution uses longest-prefix-with-digit-suffix.
  The previous greedy `re.sub(r'\d+$', '')` swallowed `L50` into mesh
  `L` and silently skipped the L5 vertebra (root cause of the toes
  disappearing during the first Save XML).
* `exportBoundingBoxes` now writes via tempfile + `shutil.move` and
  recovers on partial failure, so a runtime error inside `writeBoundingBoxes`
  no longer leaves the live XML truncated to its `<Skeleton …>` header.
  Also reads the existing on-disk XML before writing and re-emits any
  `bvh="…"` attributes per joint — fixes the bug where running Save XML
  silently stripped BVH joint mappings from the file.

Added "Mid" checkbox to Find BB so a midline OBB can be computed for
vertebrae: forces `axis="x"`, disables L↔R symmetry, and when `num_boxes
> 1` splits clusters along world Z (front/back) rather than X (left/right).
The compute_bbox routine symmetrises the X extent so the OBB sits exactly
on `x = 0`.

## Spine + sternum + shoulder structure expansion

Spine vertebrae (L5..L1, T12..T1, C7..C3, Axis0/1, Atlas0) are now real
DART bodies parented through `Saccrum_Coccyx0`. `tools/make_run_vert_bvh.py`
expands the BVH hierarchy to include them and redistributes the source
BVH's `Spine`, `Spine1`, `Neck`, `Head` rotations across the vertebrae
via quaternion `q^(1/n)` so the cumulative chain rotation equals the
original pivot rotation. Outputs `walk_vert.bvh` and `run_vert.bvh`.

Sternum, ribs 1-12 (per side) and the shoulder chain
(`Clavicle → Scapula → Humerus`) joined the skel XML through Edit Mode.

`tools/add_sternum_to_bvh.py` solves the sternum joint motion:

* 20 rib endpoints (L+R, ribs 1–10) treated as virtual contact points
  rigidly bound to their parent thoracic vertebra at rest. The anterior
  rib tip is picked as the vertex with maximum +Z (Zygote anterior axis).
* Per frame: each rib endpoint world position computed via parent
  vertebra's DART transform. Sternum's rigid transform R(f), t(f) is the
  weighted Kabsch fit of rest endpoints onto current endpoints. Upper ribs
  carry higher weight (`10,10,5,2,1,1,1,1,1,1`) so the manubrium tracks
  rib 1-3 tightly while the lower sternum absorbs the bend.
* Pivot anchor = midpoint of L/R Rib1 anterior tips (sternal notch). This
  keeps the upper sternum at rest distance from rib 1 across motion.
* LBS solve picks a constant `local_offset` in T2's body frame that best
  reproduces the anchor's per-frame trajectory. Per-frame local rotation
  for the Sternum joint = `R_T2_rest @ R_T2(f).T @ R_Kabsch(f)`. Column
  layout fix: the Sternum channels are inserted at the pre-order position
  matching the new hierarchy, not appended at the end of the row, so
  downstream joints' channels stay aligned.

`tools/add_sternum_to_skel.py` writes the Sternum0 entry into the skel XML:
X-aligned PCA OBB (X = world X, Y/Z from a PCA on the YZ plane with sign
flips so +Y points up and +Z points anterior), body anchor at the bbox
center (not the vertex mean — the manubrium has biased vertex density that
shifts the mean 18 mm above the geometric center, causing the visible Y
gap between OBB and OBJ), joint pivot at the same bbox-or-rib1 anchor so
the DART box and OBJ render at the same world point.

## Arm retargeting (per-joint frame-0 subtraction)

`bvh_info` attrs added for `L/R_Clavicle0 → LeftShoulder/RightShoulder`
and `L/R_Humerus0 → LeftArm/RightArm`.

Direct BVH binding puts the humerus ~70° off N-pose at frame 0 because the
BVH actor's frame-0 pose has the arm hanging while BVH's hierarchy zero is
T-pose. A global `T_frame=0` fix would have desynced the legs (right knee
ended bent forward because walk's frame 0 stance is asymmetric — left leg
nearly straight, right leg flexed mid-step).

`tools/bake_arm_retarget_bvh.py` subtracts frame-0 local rotation per arm
joint only: `new_R_local(f) = R_local_0.inv * R_local(f)`. Other joints
untouched. Output: `walk_vert_sternum_arm.bvh` and `run_vert_sternum_arm.bvh`.
Arms hang at N-pose at frame 0, knee motion stays correct, walking arm
swing remains.

`_detect_bvh_tframe` reverted to its leg-only heuristic so a future LaFAN1-
style flat skeleton still triggers the global correction without affecting
walk/run.

## Import zygote_skel button rebuild

The mid-session "Import zygote_skel" button now rebuilds every piece of
state a fresh viewer launch would touch:

1. Rescan `Zygote_Meshes_251229/Skeleton/` for new OBJ files (e.g. dropping
   `L5.obj` mid-session) and load them into `v.zygote_skeleton_meshes`,
   re-sorting and refreshing `cand_parent_index`.
2. Rebuild DART skel from the saved XML.
3. Rebuild `v.env.muscles` from cached `v.env.muscle_info` so the C++
   handle no longer dereferences dangling body-node pointers.
4. Re-`init_soft_body` on every muscle that already had `soft_body`, then
   `resolve_skeleton_attachments` so index-based references survive the
   skel rebuild.

The "Import zygote_muscle" button now calls this skel reload first so a
single click picks up the latest XML.

Also added `core/env.py:317` safety: if a fiber references a bone that is
not in the current skel, the fiber is skipped with a log line instead of
DART segfaulting inside `addMuscleWeight`.
