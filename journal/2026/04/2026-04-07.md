# Research Journal — 2026-04-07

## TetGen Tetrahedralization for Muscle Simulation

### Goal
Replace the contour-guided tetrahedralization (1 tet per surface face, elongated, 84% inverted for multi-stream) with proper quality tet meshes using TetGen.

### TetGen Integration
- TetGen runs in a **subprocess** to isolate crashes (segfaults from self-intersecting meshes)
- `nobisect=True`: TetGen only adds interior Steiner points, preserves surface vertices
- `steinerleft` parameter controls total vertex count
- Quality params: `mindihedral=5, minratio=2.0`

### Single-Stream Muscles (TFL, Adductor Brevis, etc.)
- TetGen works directly — 0 inverted tets, well-shaped interior
- Tet edges now draw from tetrahedra (not just render faces) — shows interior structure
- Tet edge drawing decoupled from tet mesh drawing

### Multi-Stream Muscles (Adductor Magnus)
**Problem**: shared cut-boundary vertices create non-manifold edges that TetGen can't handle.

**Solution — per-stream tetrahedralization**:
1. `build_contour_mesh` no longer merges cross-stream vertices. Each stream has its own vertex set.
2. Records `_shared_vertex_pairs` — pairs of vertex indices that represent the same contour point across streams.
3. `tetrahedralize` splits faces by stream, caps each stream independently, TetGens each.
4. For streams where TetGen fails (thin geometry): Delaunay + `mesh.contains()` filter as fallback. Preserves all original vertices and cap status.
5. After per-stream processing: **deterministic merge** using the known shared vertex pairs. No position matching, no tolerance guessing.
6. Removed Step 0.5 vertex merge (was re-merging separated streams).

### Cap Face Detection
- Cap vertices tracked through the pipeline: original contour mesh → capping → subdivision → TetGen/Delaunay
- Cap faces = faces where all 3 vertices are in cap vertex set
- For anchors with lost caps (pymeshfix or Delaunay path): plane-based recovery from surviving cap verts
- Cap detection uses anchor positions saved before TetGen modifies vertices

### Waypoint Barycentric Coordinates
- Always clamp negative bary coords (prevents opposite-direction overshoot in deformed/inverted tets)
- Live recompute fallback when cache has no waypoints (Phase 2 IPC output)
- Waypoint bary coords cleared from tet files to force recomputation with fixes

### Waypoint Recompute Fix
- `_motion_patch_waypoints` now temporarily disables fix_x/fix_z/fix_rotation during recomputation
- Cached positions were baked with original pose, not fixed pose

### Phase 2 IPC Bake
- Two-phase approach validated: ARAP bake → IPC contact resolution
- Per-frame: ARAP positions as rest shape, SPC on cap vertices only, IPC contact
- Validated on 3 muscles: 0 shrinkage, 0 detachment, fast convergence
- Full 50-muscle bake: ~3-4s per frame on A6000 GPU
- Bake outputs full vertex arrays (unmapped vertices via barycentric interpolation)

### Cap Triangulation Evolution
- **Pole-of-inaccessibility fan**: original approach, creates long thin triangles reaching to center point — self-intersects on concave 3D contours
- **Ear clipping**: 2D-projected ear clipping fails on concave 3D contours (2D projection doesn't preserve 3D planarity)
- **Zigzag**: connects from both ends alternately — too long for elongated loops
- **Unconstrained Delaunay + centroid filter**: triangles cross concave notches (doesn't respect boundary)
- **Min-area DP**: picks degenerate zero-area slivers (near-collinear triplets) — invisible triangles leave visual gaps
- **CDT (constrained Delaunay)**: ✅ final approach. Projects to best-fit plane, tries 4 projections (best-fit, XY, XZ, YZ) to avoid self-intersection, falls back to centroid fan if all self-intersect. Boundary edges preserved → no crossing concave regions.

### Boundary Loop Tracer Fix
- **Old**: vertex-based traversal with global visited set — failed at T-junctions (vertices with 3+ open-edge neighbors), picked wrong branch → OPEN loops
- **New**: edge-based traversal with face consistency — at each vertex, picks the next boundary edge sharing a face with the incoming edge. Correctly navigates T-junctions.
- Adductor magnus: 5 T-junction vertices (degree 4), all 4 loops now CLOSED

### Open Issues
- Adductor Magnus small stream: TetGen fails on thin geometry, falls back to Delaunay (lower quality tets)
- The contour mesh for this stream has close opposing faces (2-3mm apart) — not actual intersections but TetGen can't handle it
- Delaunay+inside doesn't guarantee full volume coverage in thin regions
