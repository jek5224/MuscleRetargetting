## Bone Attachment Fixes (Major Debugging Session)
### Problem: Cap vertices not following correct bones
Multiple interacting issues discovered and fixed:

1. **Empty `attach_skeletons`**: Tet files had no skeleton attachment data → all indices = 0 → wrong bone
   - Fix: Populated `attach_skeleton_names` from zygote_muscle.xml for all 50 muscles

2. **Bogus stream indices in cap_attachments**: Contour stream indices (0-99+) used instead of waypoint stream indices (0-1)
   - Fix: Recomputed using waypoint position matching

3. **Wrong end_type (origin/insertion swap)**: Cap boundary loops matched to wrong waypoint end
   - Fix: Used nearest waypoint POINT (not mean) with KD-tree for reliable matching

4. **Cap group membership by distance**: Non-cap fixed vertices assigned to wrong group when muscle spans long distance
   - Fix: BFS through cap face connectivity to group cap vertices, nearest group VERTEX (not centroid) for remaining

5. **Skeleton rest pose for local_pos**: `_compute_waypoint_barycentric_coords` and bone attachment computed at walk frame instead of rest
   - Fix: Reset skeleton to rest before computing local_pos

6. **XML origin/insertion swapped**: Superior Gemellus XML had origin=Femur, insertion=Os_Coxae (anatomically reversed)
   - Fix: Corrected attach_skeleton_names based on anatomy

### Root cause pattern
Cap vertices assigned to wrong bone → fixed_targets from wrong bone transform → vertices follow wrong bone → push through muscle body or separate from neighbors
