# Research Journal — 2026-04-22

## Fix original tet ARAP face tearing (TetGen Steiner points)

### Symptom
Visually, vertex positions in baked original-mesh ARAP output looked correct, but render_faces appeared torn / broken during deformation. Reproduced on L_Vastus_Lateralis with dance.bvh.

### Root cause
`tools/bake_original_mesh.py:tetrahedralize_mesh` called `tg.tetrahedralize(...)` without `nobisect=True`. TetGen added Steiner points on the OBJ boundary, splitting each OBJ triangle into multiple tet-boundary triangles. `tools/tet_from_original_obj.py` then remapped OBJ faces via KDTree nearest → `render_faces` referenced vertex triples that were NOT actual tet faces (106/1266 invalid on L_Vastus_Lateralis). During ARAP those 3 verts moved independently (no common tet element constraining them) → triangles stretched arbitrarily.

### Fix
`tools/bake_original_mesh.py:315` → pass `nobisect=True`. TetGen now preserves input surface exactly: every OBJ face ↔ one tet boundary face.

### Verification
- Before fix: 106/1266 render_faces invalid, max area ratio 14.5× after ARAP
- After fix:  0/1266 invalid, render_faces ⊆ tet boundary
- Regenerated `tet_orig_open/L_Vastus_Lateralis_tet.npz` (650 verts, 2072 tets, 1266 render_faces)
- Re-baked dance.bvh frames 60–70 → `data/motion_cache/dance/layered_coll_indep/L_Vastus_Lateralis_chunk_0000.npz`
- 46/2072 inverted tets remain after ARAP — separate convergence issue, not the indexing bug.
