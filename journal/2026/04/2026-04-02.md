# Research Journal — 2026-04-02

## pyuipc Simulation Setup on A6000 Server

### Initial Setup
- pyuipc (CUDA IPC solver): `import uipc` on the A6000 server
- StableNeoHookean elastic + SoftPositionConstraint (SPC) for skeleton-driven targets
- Skeleton-driven LBS positions as SPC targets per frame
- Fixed unused vertex issue: zero rows in stiffness matrix → NaN in preconditioner. Removed unused vertices via remap.

### LBS Bindings
- `compute_lbs_bindings`: 2-bone axis projection (origin/insertion) with weight clipping
- `_find_body` helper: exact match → "0" suffix → fuzzy name matching for DART body nodes
- `compute_local_anchors`: fixed vertices assigned to nearest bone by joint center distance

### Contact Attempts
- IPC contact with SPC: didn't converge (SPC pulls muscles to overlapping positions, IPC pushes apart → oscillation)
- Tried d_hat=0.1mm, SPC=1e4: residual stuck at 237mm
- Tried frame-0 initialization (start from walk pose, not T-pose): tet inversions from LBS deformation crashed pyuipc
- Contact disabled for initial bake

### Tet File Optimization
- `strip_tet_for_sim.py`: strips heavy keys (mvc_weights 3.5MB, stream_bounding_planes 1.3MB) from tet files — 94MB→24MB
- Bary coord caching: computed once, saved back to tet file for fast subsequent loads
- `_save_bary_coords_to_tet`: saves waypoint_bary_coords to tet file

### Bake Pipeline
- `bake_pyuipc.py`: skeleton-driven LBS + SPC + pyuipc elastic solve
- `slurm_pyuipc.sh`: SBATCH script for GPU job submission
- `convert_pyuipc_to_cache.py`: un-remaps vertices, converts mm→viewer scale for motion cache
- Submitted via slurm: `sbatch tools/slurm_pyuipc.sh --bvh data/motion/walk.bvh --frames 0-131 --sides LR`

### Walk.bvh Bake (No Contact)
- 50 muscles, 132 frames, ~77 seconds on A6000
- Converged in 1-2 Newton iterations per frame
- ~0.1% tet inversions (much better than walk1_subject1)
- Cache at `data/motion_cache/walk/`
