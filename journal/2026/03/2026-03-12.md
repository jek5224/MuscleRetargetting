# Research Journal — 2026-03-12

## Fix optimizer/scheduler checkpoint resume in training scripts

Applied the same checkpoint resume pattern from `dance_overfit_v1dec.py` to three other training scripts.

### Changes per file

**`walk_overfit_mirror_v1dec.py`**
- Added `optimizer.load_state_dict(ckpt["optimizer_state_dict"])` on resume (guarded by key presence)
- Added `optimizer_state_dict` to saved checkpoint dict
- Added `last_epoch=start_epoch if start_epoch > 0 else -1` to `CosineAnnealingLR`

**`walk_overfit_mirror_v2.py`**
- Same three changes as above
- Fixed a bug: `resumed_run` variable was referenced before assignment if no checkpoint existed. Replaced with the cleaner `run_name = None` + `if not run_name:` pattern used in the reference file.

**`train.py`**
- This script had no resume logic at all. Added resume from `latest.pt` (which is the periodic save every 10 epochs and already had `optimizer_state_dict`).
- Added `optimizer_state_dict` and `run_name` to `ckpt_base` so both `best.pt` and `latest.pt` now carry them.
- Cleaned up `latest.pt` save path (was mutating `ckpt_base` dict with `ckpt_base["optimizer_state_dict"] = ...` just before save — now unnecessary since it's always in `ckpt_base`).
- Updated epoch loop and print to use `start_epoch`/`end_epoch` variables.
- Added `last_epoch` to `CosineAnnealingLR`.
