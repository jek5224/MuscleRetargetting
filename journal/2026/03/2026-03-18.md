# Research Journal — 2026-03-18

## Collision Detection Fix: Ray-Cast Contains() vs Dot-Product

### Problem
Previous collision detection used dot-product with face normals on merged bone mesh (`process=False`) to determine inside/outside. This was unreliable:
- `process=False` gives inconsistent face normals for non-watertight meshes
- Merging disconnected bone meshes amplifies normal inconsistency
- Result: only 70 penetrations detected, massive visual muscle-bone interpenetration

### Fix
Switched to trimesh's `contains()` (ray-casting) on individual watertight bone meshes:
1. Build each bone mesh with `process=True` → watertight with consistent normals
2. Keep individual bone meshes for per-bone `contains()` queries
3. Bounding box pre-filter per bone for fast rejection
4. Merged mesh still used for nearest-point projection targets

### Results
- **2778 penetrating vertices detected** (was 70 — 40x improvement)
- **20 watertight bones** matched for contains() queries
- Single collision pass + relaxation: **6.7s/frame** (was 17s with 3 outer passes)
- Collision targets re-enforced every relaxation iteration to prevent elastic undo

### Architecture
```
Phase 1: 2/3 iterations — elastic XPBD (Neo-Hookean + distance constraints)
Phase 2: Collision detect (KD-tree → bbox → per-bone contains())
Phase 3: 1/3 iterations — relaxation with collision re-enforcement every iter
```

### Full Walk Bake
Running 132-frame walk.bvh bake, estimated ~15 min at 6.7s/frame.

## Fix Jagged Muscles from Inter-Muscle Constraints

### Problem
Bilateral inter-muscle distance constraints (732K pairs) pull some vertices hard while leaving neighbors unconstrained, creating jagged/uneven surfaces. Vertices near muscle boundaries have 20+ constraints vs interior vertices with 0.

### Fix
Two changes to `_xpbd_project_distance_jacobi` in `viewer/fem_sim.py`:
1. **2mm dead zone**: skip enforcement when `|C| < 2mm` — eliminates noise from micro-corrections
2. **Asymmetric stiffness**: separation uses 10x weaker compliance (gentle togetherness), compression keeps full stiffness (prevent overlap)

## Major Fix: Muscle Penetration, Jaggedness, and Shape Loss

### Problem
After initial dead-zone + asymmetric stiffness fix, muscles still had three problems:
1. Muscles penetrate each other (no muscle-muscle collision)
2. Jaggedness under pose changes (high-valence vertices get outsized corrections)
3. Shape deviation (muscles drift far from rest configuration)

### Three-Part Fix (viewer/fem_sim.py)

**Fix 1: Buffered distance corrections with per-vertex clamping**
- Instead of atomic_add directly to positions, accumulate in buffer then clamp
- Max displacement = 1mm per iteration per vertex
- Prevents high-valence vertices from dominating

**Fix 2: Taubin surface Laplacian smoothing**
- 2 passes of smooth (λ=0.3) + inflate (μ=-0.31) after XPBD iterations
- Built CSR surface adjacency at build time (per-muscle, no cross-muscle edges)
- Only touches ~8K free surface vertices — fast

**Fix 3: Muscle-muscle collision detection**
- Determines neighbor pairs from existing distance constraints
- AABB pre-filter → KD-tree proximity → trimesh contains()
- Projects penetrating vertices to neighbor muscle surface + margin
- Runs after smoothing, before bone collision

## VBD (Vertex Block Descent) Solver Implementation

### Motivation
XPBD Jacobi solver has fundamental convergence issues on our mesh:
- 17,929 inverted tets out of 199,264 (J range [-99K, +101K])
- Residual plateaus at 0.35 and never truly converges
- Gauss-Seidel can't resolve low-frequency errors at this mesh resolution

### Algorithm (SIGGRAPH 2024)
VBD minimizes per-vertex local energy using 3×3 Newton systems:
- Graph coloring gives ~8-11 colors (vs element coloring's 76)
- For each color, all vertices update in parallel
- Per-vertex: accumulate gradient g + Hessian H from incident tets → x -= H⁻¹g
- Stable Neo-Hookean energy (Smith 2018): P = μF + λ(J-1)·cofactor(F)
- Gauss-Newton Hessian approximation for SPD guarantee

### Implementation Details
- `VBDSolver` class in `viewer/fem_sim.py` (~950 lines total addition)
- Same interface as `UnifiedFEMSolver`: build/solve/get_muscle_positions
- Greedy vertex coloring + CSR vertex-tet incidence (build time)
- `_vbd_solve_color` Taichi kernel: per-vertex Newton from incident tets
- `_vbd_project_distance` Taichi kernel: distance constraint Newton steps
- Collision pipeline reused from XPBD (bone + muscle-muscle)
- CLI: `--sim-method vbd` in bake_headless.py
- Orchestrator auto-selects solver type via `use_vbd_sim` flag

### Convergence Issues & Fixes
Initial implementation diverged badly (66K inverted tets, J values in the billions). Root causes and fixes:

1. **No inertia regularization**: VBD paper uses `m/h² × ||x - x̃||²` inertia term to regularize the per-vertex energy. Without it, the Newton step overshoots catastrophically for large boundary displacements (LBS init gives J=[-5646, 1782]).

2. **Distance constraint race condition**: Separate `_vbd_project_distance` kernel had race conditions — multiple constraints sharing vertices modified positions concurrently. Fix: integrate distance constraint energy into per-vertex gradient/Hessian accumulation in the main VBD kernel via CSR vertex-to-constraint incidence.

3. **Sub-stepping with h ramp**: Use 5 sub-steps with h=[0.005, 0.01, 0.02, 0.05, 0.1] for gradual relaxation from heavily regularized to elastic-dominated.

4. **ARAP fallback for distorted tets**: When J<0.2 or J>5 or ||F||²>50, use simplified `P=2μ(F-I)` instead of Neo-Hookean to avoid catastrophic cofactor terms.

### Results (walk.bvh, 50 iters)
- **28K inverted tets** (same as XPBD with 30 iters)
- Per-iteration delta decreasing (0.069 → 0.061): converging
- **~27s/frame** (comparable to XPBD's ~31s)
- Stable across 4+ frames, no NaN or divergence
