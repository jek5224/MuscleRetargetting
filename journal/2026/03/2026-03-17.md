# Research Journal — 2026-03-17

## FEM / Soft Body Simulation Methods Research for Quasistatic Muscle Sim

### Requirements Recap
- Quasistatic (no dynamics/inertia)
- ~200k tets, ~44k verts, 74 muscles
- GPU accelerated
- Large deformation handling
- Volume preservation
- Bone collision (desired)
- Python/Taichi codebase

### Current Implementation
We already have `viewer/fem_sim.py` — a **custom Taichi-based quasistatic FEM solver** using:
- Stable Neo-Hookean energy: `W = μ/2*(I₁-3) + λ/2*(J-1)²`
- GPU gradient evaluation via Taichi kernels
- scipy L-BFGS-B optimizer
- Bone collision via soft penalty springs (trimesh nearest-point queries)
- Batched solver for all muscles simultaneously

**This is already close to optimal for our use case.** The research below identifies improvements and alternatives.

### Candidate Libraries & Methods

#### 1. NVIDIA Warp (warp-lang)
- **Method**: General GPU compute framework with `warp.sim` (XPBD) and `warp.fem` (PDE/FEM) modules
- **warp.sim XPBD**: Has soft body support with tetrahedral volume constraints, but known stability issues with tet collapsing. Macklin's constraint-based Stable Neo-Hookean (MIG 2021) is the basis.
- **warp.fem**: Higher-level FEM for PDEs. Supports tet meshes, sparse solvers (CG, GMRES). Has elasticity examples but primarily linear. Nonlinear would require custom formulation.
- **Quasistatic**: Not built-in for warp.sim (it's dynamics-oriented). warp.fem could do static solves.
- **GPU**: Yes, native CUDA JIT
- **Python**: Yes, pure Python API
- **License**: Apache 2.0 (NVIDIA BSD-3 for some parts)
- **Inversion handling**: XPBD is naturally robust; warp.fem depends on formulation
- **Performance for 200k tets**: Should be fast for gradient eval, but XPBD convergence for quasistatic unclear
- **Verdict**: Possible migration target but would require significant reimplementation. Our Taichi approach is already similar in capability.

#### 2. Taichi-based Options

**a) FEMcy (mo-hanxuan/FEMcy)**
- Taichi-based FEM solver, supports tet elements (linear & quadratic)
- Large deformation via Newton's method
- Customizable constitutive models
- Static/quasistatic focus (dynamics listed as future work)
- **Limitation**: C3D10 quadratic tets take ~5 min compile time. Not optimized for real-time.
- **License**: Not specified (GitHub)
- **Verdict**: Educational, but slower than our custom solver. Better for offline analysis.

**b) MeshTaichi (taichi-dev/meshtaichi)**
- Compiler for efficient mesh operations (SIGGRAPH Asia 2022)
- 1.4-6x speedup over other mesh data structures
- Neo-Hookean explicit FEM example included
- **Limitation**: Explicit integration only in examples, no quasistatic solver
- **Verdict**: Could improve our kernel performance via mesh data structure, but would require rewrite.

**c) Jukgei/Finite-Element-Method**
- 2D/3D FEM demo in Taichi, explicit and implicit methods
- **Limitation**: Demo-quality, not production-ready
- **Verdict**: Reference only.

**d) DiffTaichi**
- Differentiable physics framework, part of Taichi
- 188x faster than TensorFlow for elastic sim
- MPM-focused, not tet FEM
- **Verdict**: Useful if we need gradients through simulation (e.g., for learning), but not directly applicable.

#### 3. JAX-FEM (deepmodeling/jax-fem)
- **Method**: FEM solver built on JAX, GPU-accelerated via XLA
- Supports 3D tet elements, hyperelasticity, plasticity
- Differentiable for inverse design
- **Quasistatic**: Yes (static/nonlinear analysis is primary mode)
- **GPU**: Yes, via JAX/XLA
- **License**: GPL v3 (commercial requires contact)
- **Inversion**: Depends on formulation
- **Performance**: ~10x over commercial FEM for 7.7M DOFs
- **Limitation**: JAX ecosystem, not Taichi. Would need separate Python environment or bridging.
- **Verdict**: Strong candidate if we wanted to switch from Taichi. GPL license is restrictive.

#### 4. NVIDIA PhysX 5
- **Method**: FEM soft bodies via XPBD on GPU (CUDA only)
- Uses two tet meshes (sim + collision)
- **Quasistatic**: No — dynamics engine only
- **Python**: No direct Python bindings. Available through Omniverse/IsaacSim.
- **License**: BSD-3
- **Verdict**: Not suitable — no quasistatic mode, no Python API.

#### 5. SOFA Framework
- **Method**: Multi-physics FEM, emphasis on medical simulation
- CUDA-based nonlinear FEM, anisotropic visco-hyperelastic
- Python scripting plugin available
- **Quasistatic**: Possible via static solver
- **GPU**: Yes (CUDA plugin)
- **License**: LGPL
- **Limitation**: Heavy C++ framework, complex setup, scenegraph architecture. Overkill for our use case.
- **Verdict**: Too heavyweight. Better for surgical simulation research.

#### 6. VegaFEM
- **Method**: CPU-based tetrahedral FEM library (C++)
- Corotational, Neo-Hookean, StVK materials
- No GPU acceleration, no Python bindings
- **License**: BSD-3
- **Verdict**: CPU-only, no Python — not suitable.

### Key Papers

#### Stable Neo-Hookean Flesh Simulation (Smith, de Goes, Kim 2018)
- Our current implementation is based on this. Handles inversion robustly via `W = μ/2*(I₁-3) + λ/2*(J-1)²`.
- Closed-form eigenvalue expressions for Hessian projection.
- ~1M verts at ~1 FPS with Newton solver.

#### Constraint-Based Stable Neo-Hookean (Macklin & Müller, MIG 2021)
- Decomposes Neo-Hookean into deviatoric + hydrostatic XPBD constraints
- Order of magnitude faster for stiff volume preservation
- **Relevant**: Could replace our L-BFGS-B with XPBD iterations for faster convergence. This is what Warp's XPBD uses internally.

#### Robust Quasistatic FEM (Teran, Sifakis, Irving, Fedkiw 2005)
- Foundational paper for quasistatic flesh simulation
- Eigenvalue filtering for projected Newton — handles inversion + indefiniteness
- CG solver with guaranteed positive-definite system

#### EMU: Efficient Muscle Simulation in Deformation Space (Modi et al. 2021)
- Scales better than FEM for musculoskeletal systems
- Handles heterogeneous materials (muscle, tendon, bone) in unified system
- No model reduction needed
- **Code**: "Coming soon" — likely never released
- **Verdict**: Interesting method but no code available.

#### Penetration-free Projective Dynamics on GPU (SIGGRAPH 2022)
- GPU PD with contact handling via interior-point method
- Relevant for collision handling improvement

#### Subspace-Preconditioned GPU Projective Dynamics (SIGGRAPH Asia 2023)
- Faster PD convergence via subspace preconditioning
- Good for large meshes

### Recommendations (Ranked)

**1. Keep current Taichi solver, optimize it** (BEST)
- We already have a working quasistatic Stable Neo-Hookean solver in Taichi
- Main bottleneck: L-BFGS-B runs on CPU (scipy) with GPU gradient evals → CPU-GPU transfer overhead
- **Improvement A**: Implement Newton-CG entirely on GPU in Taichi (eliminate scipy)
- **Improvement B**: Use projected Newton with eigenvalue filtering (Teran 2005) for guaranteed PD Hessian
- **Improvement C**: Warm-starting from previous frame already implemented

**2. Switch optimizer to XPBD-style constraint iteration** (MODERATE EFFORT)
- Macklin 2021 shows XPBD with Neo-Hookean constraints converges fast for stiff volume preservation
- Could implement as Taichi kernels — all GPU, no CPU optimizer
- Naturally handles quasistatic (just run until convergence without inertia term)
- **Risk**: XPBD convergence for 200k tets with high Poisson ratio may need many iterations

**3. Migrate to NVIDIA Warp** (HIGH EFFORT, MARGINAL BENEFIT)
- Warp's JIT is comparable to Taichi for kernel performance
- Would need to reimplement everything
- Only worthwhile if we need features Taichi doesn't provide (e.g., native sparse linear algebra)

**4. JAX-FEM for offline validation** (LOW PRIORITY)
- Could use JAX-FEM to validate our solver against a reference implementation
- GPL license prevents direct integration

# Research: XPBD Neo-Hookean Constraint Formulation

## Papers Studied
1. **Macklin & Mueller 2021** - "A Constraint-based Formulation of Stable Neo-Hookean Materials" (MIG '21)
2. **Macklin et al. 2016** - "XPBD: Position-Based Simulation of Compliant Constrained Dynamics"
3. **Smith, de Goes, Kim 2018** - "Stable Neo-Hookean Flesh Simulation" (Pixar, SIGGRAPH 2018)
4. **Andrews et al. 2022** - "Parallel Block Neo-Hookean XPBD using Graph Clustering"

## Key Findings
- Neo-Hookean energy decomposes into deviatoric (C_D) and hydrostatic (C_H) constraints per tet
- XPBD uses Gauss-Seidel iteration with compliance-scaled Lagrange multipliers
- Found complete Taichi implementation in yoharol/PBD_Taichi (cons/deform3d.py)
- Coupled 2x2 block solve for C_H and C_D per tet improves convergence
- Graph coloring enables parallel Gauss-Seidel on GPU

- alexrodag/spg - C++ with auto-diff and multiple solvers
