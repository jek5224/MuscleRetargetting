# Research Journal — 2026-03-10

## Playback Frame Skip Optimization

Fixed motion playback performance issue where 120fps BVH playback was choppy even at 0.5x speed (frame slider jumping 2→16→31).

**Root cause**: The playback loop called `_motion_step_forward(self, 1)` in a while loop, applying pose+deformation for every intermediate frame — all thrown away since only the last frame is rendered.

**Fix**: Calculate total frames to skip in one shot, apply pose+deformation only once for the final frame. Sequential stepping preserved for bake mode (`run_tet=True`).

**Additional optimizations committed**:
- V1/V1Dec rest positions cached on GPU (add on GPU, single `.cpu()` transfer)
- World transform R,t cast to float32; `@ R.T` instead of `(R @ .T).T`
- Removed `.copy()` on tet_vertices, cleaned up profiling leftovers

## Research Direction: NN-Driven Waypoints for RL

### End-to-End Pipeline Vision

Joint DOFs → NN (V1Dec) → deformed tet mesh → extract waypoints → DART muscle model → RL

Replace DART's geometric wrapping (via-points, wrapping surfaces) with learned waypoints from FEM-trained NN. Key advantages over geometric wrapping:
- No routing failures at extreme poses (muscles clipping through bones)
- Smooth force transitions (no wrap/unwrap discontinuities)
- NN is differentiable — enables analytical moment arm computation
- Cross-sectional information available (geometric wrapping has none)

Main risk: out-of-distribution generalization when RL explores unseen poses. DOF grid training (covering full ROM) would mitigate this vs. motion-specific baking.

### Waypoint Extraction via MVC Sampling

Mean value coordinates (MVC) provide a consistent parameterization across all contour cross-sections. A fixed point `(u,v)` in MVC space traces a fiber path through the muscle when mapped to 3D at each contour level. This parameterization is pose-invariant — the NN-deformed tet mesh moves sample points correctly via existing barycentric/MVC machinery.

**Extraction method**: Choose N sample points in MVC parameter space → map to 3D at each contour level → connect across levels → N discrete fiber paths (waypoint sequences).

### Multiple Fibers per Muscle: Advantages for RL

1. **Moment arm accuracy** — wide muscles (e.g., Gastrocnemius) have different moment arms on medial vs. lateral sides. One centroid fiber averages them out, incorrect at extreme ROM.
2. **Force direction coupling** — multiple fibers produce coupled moments (e.g., flexion + varus/valgus) that single fibers miss. RL learns more realistic coordination.
3. **Wrapping stability** — with multiple fibers, some wrap while others don't. Net force changes smoothly instead of snapping discontinuously.
4. **Joint compression** — fibers on opposite sides of a joint produce compressive forces during co-contraction. Single central fiber produces zero compression. Enables natural co-contraction learning without artificial joint stiffness.

**Practical plan**: Start with centroid-only (1 fiber), validate moment arms against FEM, add fibers (3-5) only where moment arm error is significant.

### Active Contraction (Future Work)

Current tet simulation is passive only (muscles deform from skeletal motion). Active contraction adds fiber-aligned stress:

`σ_active = activation · f_FL(stretch) · σ_max · (f̂ ⊗ f̂)`

The contour stream scalar field (level 0 at origin → level N at insertion) directly provides the fiber direction field (its gradient). This could serve as a contraction coordinate for active stress in the taichi solver.

**Impact on NN pipeline**: Input becomes `(DOFs, activations)` → deformation, expanding the baking space. However, activation's effect on waypoint paths is secondary to joint angle effects — skip for first RL integration, add as follow-up.

**Most interesting potential**: inter-muscle interaction under contraction (contracted muscle pushes neighbors, changing their paths) — something geometric wrapping fundamentally cannot capture.
