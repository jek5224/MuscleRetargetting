# Research Journal — 2026-03-23

## Incremental Pose Loading for Collision-Correct Initialization

### Problem
LBS/ARAP initialization can teleport muscle vertices through bones when the target pose has large joint angles (e.g., deep knee bend → quadriceps through femur). Post-hoc collision projection pushes vertices to the nearest bone surface, which may be the anatomically wrong side.

### Solution
Interpolate skeleton pose from rest to target in N steps (default 10), running the full solver+collision pipeline at each step. Since muscles start at rest pose (correct anatomical side) and each step is small, collision always pushes to the correct (nearest) side — muscles slide along bone surfaces rather than teleporting through them.

### Implementation
- `_run_incremental_loading()` in `viewer/fem_sim.py`: orchestrates the loading loop
- At each step: set interpolated skeleton pose → update LBS positions + fixed targets → build bone collision meshes → run solver with limited iterations + collision
- Iteration budget distributed: early steps (80%) get 1/3 of iters, late steps (20%) get 2/3
- Subsequent frames use temporal coherence (previous solution) — no incremental loading needed
- `--load-steps N` CLI arg in `bake_headless.py`, `fem_load_steps` attribute on viewer context
- Unified `_has_previous_solution` tracking across both XPBD and VBD solvers

### Key Design Decision
Incremental loading is at the orchestrator level, not inside the solver. The solver's h-ramp sub-stepping handles elastic convergence within each load step; the orchestrator handles pose progression and collision correctness across steps. These are complementary.

## XPBD vs VBD: XPBD Wins

Tested both solvers extensively. XPBD is clearly better for this problem:
- XPBD: 28K inv tets, 25-42s/frame (Jacobi parallel, fast GPU)
- VBD: 38-46K inv tets, 260-350s/frame (Gauss-Seidel, 10x slower)

VBD's 0.5mm step clamp and h=1.0 inertia fundamentally limit convergence for 200K tets. XPBD's constraint projection converges much faster.

## Collision Quality Improvements

Three improvements to muscle-muscle collision:

1. **Signed-distance collision** (replaces contains()): nearest-point + normal dot product works on all meshes, no watertight requirement. Previously most muscles got zero collision.

2. **Contact filtering**: BFS from fixed vertices tags 3 regions — fixed (no coll), near-attachment 2-ring (bone-only), belly (full mm). Eliminates false contacts at junctions.

3. **Collision-relaxation cycles**: 2 detect-project-relax cycles (15 XPBD iters each with soft re-enforcement). Reduces remaining bone penetrations by 76% (3308 → 786).

4. **SOR acceleration**: omega=1.7 speeds XPBD convergence ~30%.

### Final Results (walk.bvh, 4 frames)
- Inv tets: 28,396 (14.3%)
- Bone penetrations remaining: 786 (down from 3,308)
- mm collisions: 2,594
- Time: 36-42s/frame
- J range: [-1.8M, +172K]
