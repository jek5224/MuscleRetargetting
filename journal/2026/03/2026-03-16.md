## Literature Survey: Multi-Body Soft Tissue Simulation with Collisions

Researched state-of-the-art methods for simulating multiple soft body muscles packed around bones with inter-body collision handling. Current system uses ARAP per-muscle independently (no collisions). Key methods found:

### Top Candidates
1. **IPC / GPU-IPC / StiffGIPC** — Barrier-based contact guaranteeing intersection-free trajectories. GPU version (GIPC) with 3x speedup; StiffGIPC adds 10x over that for stiff materials. C++/CUDA. Best correctness guarantees but heaviest compute.
2. **Taichi MLS-MPM** — Grid-based contact is "free" (bodies interact through shared grid). GPU-accelerated via Taichi. Good for many bodies, but mesh quality/resolution tradeoffs.
3. **NVIDIA Newton/Warp** — Open-source GPU engine (March 2025), supports soft bodies + rigid + cloth + MPM. Python API, differentiable. Still maturing.
4. **XPBD** — Real-time constraint-based approach. Multi-layer solver (SCA 2024) handles contact-heavy scenes. Simplest to implement but least physically accurate.
5. **PolyFEM** — C++ FEM library with IPC-based contact. Validated for biomechanics. Automatic collision detection.
6. **FEBio** — Biomechanics-specific FEM with muscle activation support and contact modeling. ABAQUS-like, not GPU-accelerated.

### Muscle-Specific Work
- Frontiers 2023: "3D continuum approach incorporating multiple muscle interactions" — cohesive contact for muscle-muscle/muscle-bone, Hill-type activation, ABAQUS/Explicit. Most directly relevant but slow (no GPU).
- Stuttgart OpenDiHu (2024): Multi-scale muscle simulation framework (FEM + activation + electrophysiology).

### Key Decision Factors
- IPC/GIPC: Best for correctness (no interpenetration guaranteed), but complex integration
- MPM via Taichi: Easiest path for many-body contact, already using Taichi in project
- XPBD: Fastest for real-time, but may need careful tuning to avoid artifacts with tightly packed bodies
- Newton/Warp: Most future-proof but still beta

## FEM Muscle Simulation Implementation

Implemented a Neo-Hookean FEM simulation module to replace/complement ARAP, with collision handling.

### New Module: `viewer/fem_sim.py`
- `FEMSimulation` class: Taichi GPU-accelerated Neo-Hookean FEM
- Newton-CG solver with finite-difference Hessian-vector products
- Bone collision: CPU trimesh nearest-point → GPU penalty gradient
- Inter-muscle contact: penalty forces when vertex pairs closer than rest distance
- Backtracking line search, J-clamping for inverted element safety
- `run_all_fem_sim()` orchestrator for multi-muscle simulation

### Integration
- UI: ARAP/FEM radio toggle + material sliders (Young's modulus, Poisson ratio, kappa)
- Bake: `--sim-method fem|arap` flag in `bake_headless.py`
- Motion settle: dispatches to FEM when `use_fem_sim=True`
